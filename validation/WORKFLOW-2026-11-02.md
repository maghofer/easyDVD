# Workflow and Blu-ray follow-up validation

Validated on Windows x64 with 16 logical CPUs. All generated media, queues,
builds and temporary files used isolated local scratch storage with process-local
TEMP/TMP/GOTMPDIR. The GUI queue was not changed. Exchange fixtures were read
only; numbered collections were not combined.

## Queue and settings

- Startup update checks run off the UI thread, cancel on close, stay silent on
  current releases/network failures, and show a release link only for an update.
  Tests cover enabled, disabled, current, unavailable and newer-release results.
- Application settings contain workers (Auto initially), work folder, theme,
  staging, retained work, updates and logs. Encoding presets exclude workers.
  Preset storage survives reopening and replaces/deletes names case-insensitively.
- Inline job controls support DVD/Blu-ray, capacity, DVD TV standard, profile,
  menu/autoplay, preset assignment and menu editing. Batch edits validate the
  entire selection and preserve other mixed values. Output-path edits capture
  their selection before opening the folder picker.
- File and job dragging moves selected blocks in order, accounts for list
  scrolling/padding, shows an insertion line, and removes its overlay on release.
  Manual file order is persisted separately from natural discovery order.
  Packing and overflow recovery always preserve strict order. The old CLI
  `-efficient` switch is accepted as an ignored compatibility option.
- Completed/failed job context menus offer Clear render status. Reset clears
  generated-media references, elapsed time and render state, retains source
  selection/titles/order, and uses a new render namespace and output-folder
  suffix. A real-tool Blu-ray queue rendered twice; the first ISO hash stayed
  unchanged and every prepared title in the second render had a new path.
- Queue completion is finalized by the coordinator after successful processing.
  PAL/NTSC Balanced and HCEnc Quality tests assert Complete, 100%, elapsed time,
  no active files and no busy job. Publication/restart recovery passed for all
  four combinations. Legacy serialized DVD settings retain their generation
  identity; new update preferences do not enter authoring identities.
- The status bar reports active preparation workers rather than the configured
  concurrency limit. Queue tiles show cumulative processing time, excluding
  queue waits and pauses. The tools box generates command examples from the
  production profile builders. Commands in diagnostics/logs quote literal paths
  and filters, including spaces, apostrophes and shell metacharacters.

Light/dark headless captures were inspected, including the two-row inline header
and mixed-value multi-job header. Settings, preset controls, playback and existing
file/queue selection regressions passed.

## Blu-ray menus

The user reported immediate playback in PotPlayer and Media Player Classic.
[MPC-HC's release documentation](https://github.com/clsid2/mpc-hc/releases/)
explicitly states that Blu-ray menus are unsupported. Main-movie playback in
that player cannot validate authored navigation. PotPlayer menu behavior has
not been independently verified.

The existing mixed-format multi-page ISO and an ISO produced by the actual
easyDVD backend were opened through locally installed libVLC 3.0.24 with HDMV
menus enabled and isolated configuration. Both started on the menu, moved to
title two, activated it, and returned to the menu. Memory-output captures showed
the selected button graphic; the app-authored ISO also showed changed menu
pixels when selection moved. `bluray-vlc-check.py` reproduces this without
changing VLC's saved settings. Snapshot API output omits IG overlays, so raw
memory-output frames were also captured and visually inspected.

An initial dummy-video-output attempt encountered GPU-surface blending errors
and crashed during teardown. Validation switched to software memory output and
completed cleanly. This is a player/output-path limitation in the validation
harness, not evidence for hardware-player compatibility. Independent libbluray
tests continue to cover menu pages, Play All, title/page returns, seeking and
autoplay stopping. Single-video autoplay remains the default.

## Performance measurements

The AVC verifier previously continued running FFmpeg's trace-header pass after
an early rejection. It now cancels that inspection process at the first definite
failure. Accepted copy candidates still require full-stream inspection. Parent
cancellation is propagated separately from ordinary encode fallback.

A four-minute 1080p24 H.264 fixture outside the verifier's accepted reference
subset took 1.900 s for the previous full inspection versus 0.041 s to reject
early (46× for this stage). This does not claim a 46× end-to-end encoding gain.
`TestBlurayInspectionEarlyRejection`, enabled with EASYDVD_AVC_BENCH, reproduces
the comparison using an explicit staged input.

Blu-ray had inherited DVD's eight-thread per-process ceiling. HD AVC can now use
up to 16 threads, sharing available CPU across concurrent titles and leaving
two logical CPUs of headroom. DVD's budget is unchanged. A read-only 6.875-second
1080p24 DNxHD fixture was staged once. Reversed-order repeat measurements used
identical filters, x264 presets/CRF and Blu-ray limits; only thread count changed:

| Profile | 8 threads, mean | 14 threads, mean | Encoding time reduction |
|---|---:|---:|---:|
| Balanced, medium/CRF 20 | 2.86 s | 1.99 s | 30% |
| Quality, slow/CRF 18 | 4.62 s | 3.34 s | 28% |

A separate production-pipeline comparison included decoding/scaling, audio,
complete decode validation and hashing for four copies of the staged title:

| Profile | 2 workers | 4 workers |
|---|---:|---:|
| Balanced | 7.752 s | 6.610 s |
| Quality | 13.168 s | 13.012 s |

Auto therefore starts from CPUs/4 for Balanced and CPUs/8 for Quality, capped at
four, before pending-title, memory and disk-space limits. This is a measured
starting policy, not a guarantee for every machine/source. A fixed worker choice
remains available globally. `TestBlurayParallelThroughput` reproduces the four-title
comparison when EASYDVD_BLURAY_BENCH_INPUT is set; EASYDVD_BLURAY_BENCH_REPORT
selects a scratch JSON report. Encoder presets, quality targets, AVC restrictions
and full decoding validation were retained.

## Checks

- `go test ./...` and `go vet ./...` passed.
- Race checks passed for media, engine, subprocess, model, packing and storage.
- The full real-tool DVD/Blu-ray integration suite passed in 54 seconds, including
  copied/encoded AVC, SD/720/1080 modes, surround/silence, mixed menus,
  cancellation, resume, reset, capacity handling and HCEnc mux/frame regressions.
- A portable Windows preview and matching source package were built. With PATH
  restricted to Windows system directories, its bundled authoring runtime
  completed a four-title Quality Blu-ray job with two menu pages and reached
  Complete/100%. FFmpeg was supplied explicitly; system Python and Java were
  unavailable to the run. Packaging used an isolated source export excluding
  the two pre-existing private-path notes described in the earlier Blu-ray
  validation report; the export's source audit passed. No release was published
  or installer run.
- Software validation remains the release gate. Standalone players and burned
  optical media remain unverified; Blu-ray remains experimental.
